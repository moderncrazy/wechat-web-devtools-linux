# 小程序 DOM 探索持续超时排查（2026-10-28）

场景：通过 miniprogram-automator 从主页面触发连续 reLaunch，主页面因未认证跳转到游客页面。当前页面查询可以返回，但 `$$` 和页面数据读取持续出现服务端 10 秒超时。

## 已复现的两层故障

1. 路由队列：尚未 ready 的页面被下一次 reLaunch 销毁后，未发送路由事件的队列项仍占据队首。真实日志中页面 9 已销毁，页面 10 ready/done，但旧队列项阻止页面 10 的 OnAppRoute 发往逻辑层。逻辑页面与实际 WebView 不一致，DOM 没有完成初始化。
2. SDK 代理生命周期：单独修复路由队列后，第二轮仍出现真实 WebView 已有 17 个 view、DOM 已完成，而 DOM RPC 持续超时的情况。代理在等待 ready 时跨页面共享原生订阅；回调中删除原生监听器会改变正在异步遍历的数组，可能漏掉其他等待者。未完成的握手 Promise 被永久缓存，后续同页查询也一直等待。原版还在等待前分配回调 ID，等待后使用可变化的目标页面，存在请求乱序与串页风险。

## 修复范围

- reLaunch 开始时移除尚未发送路由事件的旧队列项；保留已发出的路由及普通栈导航行为。
- SDK 使用一个稳定的 ready 订阅，在自己的等待集合中分发事件；不在原生订阅遍历时删除回调。
- 握手在 9 秒无响应时清理失败缓存，让下一次显式请求可以重新初始化。保留开发者工具原有的 10 秒 RPC 上限，不自动重放业务命令。
- 请求捕获原页面目标，在 ready 后分配回调 ID，避免等待期间变更目标或以旧 ID 覆盖新请求。
- 按上游模块形状唯一定位并追加运行时补丁；不修改官方压缩源码主体。

## 验证记录

- 从正在运行的工具提取真实 RouteController：原版回归失败，补丁后通过。
- 从 SDK 提取的代理代码：原版能复现跨页面等待者被遗漏；补丁回归覆盖异步订阅、独立 Runtime/DOM 目标、握手失败后重新初始化及监听器数量有界。
- 相关 Node 回归共 35 项通过；构建脚本通过 bash 语法检查，git diff --check 通过。
- 带临时诊断的真实容器连续完成 5 轮主页面→游客页面导航。每轮稳定页面均返回 17 个 view；5 轮稳定页 $$ 耗时 79–115ms，数据及属性读取通过。
- 切换过程中对已销毁 Page 的故意查询仍会失败；测试会记录该失败，并重新获取当前 Page 后验证稳定 DOM。不能把旧 Page 超时等同于最终页面持续不可操作。
- 去除全部临时诊断入口和事件钩子后，正式容器再次通过 5 轮同样回归；5 轮稳定页 $$ 为 84–140ms。
- 正式容器额外连续 3 次验证单元素查询确实返回元素（37–54ms），不存在的选择器正常返回 null（47ms），排除把 SDK 吞错返回 null 误当成功。
- 主进程及视图生命周期模块与原始内容逐字节一致；仅路由与 VendorService 模块追加正式补丁。Agent 服务源码未修改。
- 镜像 `budtech-regression/wxdt-automator:20261028-dom-fix` 已构建，ID `sha256:53ee99c166db`（前缀）；原有 `20261027` 标签指向同一修复镜像。无网络、无用户数据的镜像静态检查确认补丁内容与正式容器一致。现有容器完成了代码更新和重启，6080、9420 仍对所有地址开放。

## CPU、内存

宿主机 4 核、约 15GiB 内存，容器内存限制 8GiB，无 CPU 配额限制。

| 阶段 | 实测 |
| --- | --- |
| 原问题持续卡住、编译已经结束 | 50 个样本，CPU 16.07%–75.88%，内存最高 1.988GiB |
| 单独路由补丁连续导航 | CPU 峰值 383.18%，内存峰值 4.828GiB |
| 组合补丁连续 5 轮导航 | CPU 峰值 381.37%，内存峰值 5.374GiB |
| 无诊断的正式补丁 5 轮导航 | CPU 峰值 383.5%，内存峰值 5.032GiB |
| 组合回归中宿主机内存快照 | 可用 10348MiB |
| 导航结束后稳定快照（23:35:04） | CPU 10.70%，内存 2.556GiB / 8GiB |
| cgroup OOM / OOM kill / CPU throttling | 均为 0 |

结论：编译和连续切页会显著消耗 CPU、增加内存，可能放大初始化期间的延迟；已复现的稳定页持续 DOM 超时有明确的路由及握手生命周期原因，不能通过单纯增加超时时间解决。未进行长时间内存泄漏测试，不据此承诺无限轮次的内存稳定性。
